# Phase 02.3-03 Summary

**The legacy card quiz flow has been replaced with a production chat-driven answering experience that preserves scoring semantics, answer revision, and incomplete-submit recovery**

## Performance

- **Duration:** 20 min
- **Completed:** 2026-04-22
- **Tasks:** 3
- **Files modified:** 8

## Accomplishments

- Built `apps/web/src/features/quiz-chat` as the new answering boundary: a scene adapter turns `questions + answers + currentQuestionIndex + submitMessage` into a real message timeline instead of reusing `question-frame`.
- Migrated the answering stage to `ChatQuizFlow`, including send animation, delayed auto-advance, revision rail jumps, and a "回到最新进度" affordance that keeps the chat feeling intact.
- Preserved incomplete-submit guidance under the new auto-advance UX by adding an explicit "直接看结果" action that routes back to the first unanswered position through the existing App submit logic.

## Files Created/Modified

- `apps/web/src/features/quiz-chat/model/chatScene.ts` - Adapts runtime quiz state into `DialogueMessage` history, revision entries, and submit notices.
- `apps/web/src/features/quiz-chat/model/chatScene.test.ts` - Covers answered history, revision prompt behavior, and pending-send rendering.
- `apps/web/src/features/quiz-chat/ui/ChatQuizFlow.tsx` - Production LINE-like answering surface with auto-scroll, auto-advance, revision rail, and incomplete-submit CTA.
- `apps/web/src/features/quiz-chat/ui/chat-quiz.css` - Layout and visual treatment for the chat panel, revision rail, and migration guardrails.
- `apps/web/src/pages/home/sections/HomePageSections.tsx` - Swapped the old `question-frame` branch for `ChatQuizFlow` and updated migration copy to reflect intro+quiz migration progress.
- `apps/web/src/pages/home/HomePage.tsx` - Rewired answering-stage props around the new chat feature and removed legacy quiz-card scene scaffolding.
- `apps/web/src/app/App.tsx` - Kept answer recording and submit semantics stable while letting the chat UI own transition timing; updated shell copy to reflect the new runtime state.

## Decisions Made

- Let the App continue owning answer persistence and `MatchComputation`, but move "when to advance" into the chat UI so animations can finish before the next question appears.
- Keep revision and incomplete-submit handling explicit in the UI instead of assuming the sequential chat flow makes those states impossible.
- Leave result-page fallback in place and only update shell copy/status to match the new intro+quiz migration truth.

## Deviations from Plan

- Added the explicit "直接看结果" action. This was a small UX deviation from the written tasks, but it was necessary to preserve and browser-test the existing "jump to first unanswered question" submit behavior after moving to enforced chat auto-advance.

## Issues Encountered

- `npm run dev:web -- --port 4173` through the root workspace wrapper was parsed incorrectly by npm and produced a Vite process that returned `404` at `/`. Browser QA was rerouted to the correct workspace command: `npm run dev --workspace apps/web -- --port 4173`.
- Canonical API port `3001` remains blocked in this WSL session, so browser QA stayed on `api@3002` with `VITE_API_PROXY_TARGET=http://127.0.0.1:3002`.

## Verification

- `npm run typecheck:web`
- `npm run test --workspace apps/web`
- `npm run build:web`
- Headless Chrome browser QA on `http://127.0.0.1:4173/` with `api@3002`
- Browser QA result: sequential headers advanced through `Q01` → `Q05`, revision rail reached `5` entries, message log auto-scrolled (`scrollTop=1506`, `scrollHeight=2197`, `clientHeight=328`), incomplete submit produced `还有 15 题没选`, and revising `Q03` changed the stored answer before resuming at `Q06`

## Next Phase Readiness

- `02.3-04` can now treat the answering flow as migrated and focus entirely on rebuilding the result page into modular template-era sections.
- Result-stage fallback is still intact, which keeps poster export and current result behavior available while the next plan rewires hero/media sections onto the asset resolver.
- Keep using `api@3002` or clear the stale `3001` listener before attempting canonical local proxy QA again.
