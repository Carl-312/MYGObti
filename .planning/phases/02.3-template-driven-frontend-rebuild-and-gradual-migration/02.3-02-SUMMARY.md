# Phase 02.3-02 Summary

**Production chat atoms, manifest-backed character asset contracts, and a shell-mounted browser preview route now sit on top of the existing legacy quiz boundary**

## Performance

- **Duration:** 75 min
- **Completed:** 2026-04-22
- **Tasks:** 3
- **Files modified:** 19

## Accomplishments

- Ported the template chat semantics into `apps/web/src/shared/ui/dialogue` with reusable `DialogueAvatar`, `DialogueBubble`, `DialogueRow`, `DialogueList`, message types, send animation, row entrance, choice fade, and auto-scroll.
- Built `apps/web/src/entities/character/model/characterAssets.ts` plus UI slots for round avatars and Live2D static art, and normalized the runtime ids to the manifest truth (`raana`, `uika`).
- Added `/preview/chat-atoms` under the current shell so browser QA can validate chat playback and all 8 asset slots before the quiz or result pages are migrated.

## Files Created/Modified

- `apps/web/src/shared/ui/dialogue/*` - Production chat primitives and styles copied from template semantics into runtime code.
- `apps/web/src/entities/character/model/characterAssets.ts` - Manifest-driven asset resolver with alias normalization and placeholder contract.
- `apps/web/src/entities/character/ui/*` - Reusable round avatar and Live2D slot components.
- `apps/web/src/pages/preview/ChatAtomsPreviewPage.tsx` - Browser QA surface for chat playback and asset cards.
- `apps/web/src/entities/character/model/characters.ts` - Corrected runtime ids and relationship references to match manifest-backed asset ids.
- `apps/web/src/shared/ui/story-svg/StorySvg.tsx` - Moved accent-color lookup onto the normalized character asset contract.
- `apps/web/src/app/App.tsx` - Registered the preview route and shell navigation entry.

## Decisions Made

- Kept the legacy quiz flow mounted on `/` and did not touch `apps/api`, `packages/quiz-core`, or `/api` proxy semantics.
- Treated the manifest ids as canonical runtime truth and normalized old frontend-only aliases instead of cloning more asset exceptions downstream.
- Added a deterministic `?choice=...` preview hook so headless browser QA can verify the post-selection state without wiring the full quiz flow first.

## Deviations from Plan

- None in product scope. The only environment deviation was QA-related: default API port `3001` was blocked by a Windows-side `Cursor.exe` listener, so API smoke testing was confirmed on `3002` instead of the canonical local port.

## Issues Encountered

- `npm run dev:api` on the default port still cannot bind to `3001` in this WSL session because Windows `Cursor.exe` is listening on `127.0.0.1:3001`.
- The API code itself is healthy: `PORT=3002 npm run dev:api` returned `200` for `/api/quiz/meta`.

## Verification

- `npm run typecheck:web`
- `npm run test --workspace apps/web`
- `npm run build:web`
- Headless Chrome browser QA on `http://localhost:5173/preview/chat-atoms?choice=choice-2`
- Browser QA result: `rows=6`, `sentBubbles=1`, `assetCards=8`, status text reached `resolved`, and follow-up replies included `椎名立希` / `长崎爽世`

## Next Phase Readiness

- `02.3-03` can now migrate the answering flow onto `shared/ui/dialogue` instead of re-implementing chat presentation.
- `02.3-04` can consume the character asset resolver and the slot components directly for result-page hero/media work.
- Before relying on the canonical `/api` QA loop again, free Windows-side port `3001` or move the conflicting host listener.
