## Decisions Made

- Avoided pulling in the template's Tailwind runtime for this first step; copied only the shell concepts and implemented them with the current CSS stack to keep cutover risk low.
- Treated the new shell as the product-level boundary and the stage sections as the migration-level boundary, so later work can replace the answer flow or result view independently.
- Used app-visible QA chrome plus `.planning` handoff docs to reinforce the “persistent servers + browser acceptance” workflow instead of leaving it as an implied team habit.
