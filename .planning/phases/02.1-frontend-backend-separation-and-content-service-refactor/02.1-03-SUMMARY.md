# Phase 02.1-03 Summary

**Web runtime content now loads from the read-only API with a typed Vite proxy path, resilient boot/failure states, and updated local/deploy runbooks**

## Accomplishments

- Replaced the web app's direct canonical Markdown import path with runtime loading from `/api/quiz/meta` and `/api/quiz/content`.
- Kept result scoring in `packages/quiz-core` and moved the shared API contract there so neither the web nor API side duplicates matching logic.
- Added a boot shell for initialization, readable failure messaging, retry/refresh actions, and preserved the existing V2.1D quiz/result/share flow once content is loaded.
- Wired `apps/web` to use Vite `server.proxy`, typed `VITE_API_BASE_URL` / `VITE_API_PROXY_TARGET`, and refreshed README / architecture docs for split-stack startup and deployment.

## Decisions Made

- Kept `/api` as the default runtime path so the browser can stay environment-agnostic in local development and same-origin deployments.
- Left character presentation copy in the web layer, but only as a decoration step on top of API-delivered canonical character anchors and metadata.
- Removed the obsolete web-side canonical import files instead of leaving a second runtime truth available by accident.
