# Architecture

## 目标

这个仓库是一个零后端、纯前端的 H5 小项目，所以工程分层要够清楚，但不能重到像企业中台。
当前采用“页面组合 + 功能模块 + 领域实体 + 共享基础”的轻量前端分层。

## 分层职责

- `src/app/`
  - 应用入口、全局样式、全局 providers
- `src/pages/`
  - 页面级拼装，不承载复杂算法
- `src/features/`
  - 答题流程、结果匹配、分享生成等交互功能
- `src/entities/`
  - 角色、题目、结果卡等领域数据与最小展示单元
- `src/shared/`
  - 通用类型、纯函数、基础配置

## 当前边界

- 角色坐标、题库、结果文案都先走本地内容文件
- 不引入后端、不引入账号系统、不引入 CMS
- `.planning/` 只负责执行文档，不能变成产品说明副本

## 后续扩展建议

- 如果题库和文案体量变大，可把 `src/entities/**/model/*.ts` 逐步迁移到 `src/content/**`
- 如果结果海报复杂，可以在 Phase 2 引入独立的分享 feature 层
- 如果需要更多视觉原子组件，再补 `src/shared/ui/`
